# Prometheus soundpack

MUSHclient soundpack for Prometheus: The Eternal Wars. Shane's repo (`stickbear2015/prometheus`), inherited from another author (the plugin says "Krinnzenn"), so it's messy.

## Layout

- `prometheus/`: the packaged MUSHclient folder that players get (mushclient.exe, DLLs, sounds and scripts).
  - `worlds/EternalWars.mcl`: the world file.
  - `worlds/plugins/Prometheus.xml`: the main plugin. It holds the header, the aliases and the script block, and pulls in the triggers from `worlds/plugins/prometheus/<area>.xml` (system, comms, starship, combat, activities, devices, vehicles, socials, refusals, game, household, teleporting, money, groups, health, items, games, general, gags). Each trigger names a Lua function in `lua/prometheus/triggers/<area>.lua`, which gets `(name, line, wildcards)`. (On `dev` it's still one 8,781-line file with the Lua in the send boxes.) MUSHclient looks for a plugin's includes in its plugins folder, `worlds\plugins`.
  - `worlds/plugins/`: other plugins (channel_history, output_functions, universal_text_to_speech, LuaAudio and so on).
  - `lua/prometheus/`: the started modern modules: `main.lua`, `core/` (bootstrap, config, plugin, Sound), `sounds.lua` (`OnOOBmsg` for `#$#soundpack` lines), `help.lua`, `macros/`, `util.lua`.
  - `sounds/`: about 1,900 .ogg files (Combat, Footsteps, General, Music, Rooms, Socials, Starship, Vehicle).
- `original sounds/`: a temporary copy of the sounds from before they were trimmed (issue #36). To be removed once the edge cases are fixed.
- `changelog.md`: the player-facing changelog; the "development version" section lists unreleased changes with issue links.
- `prometheus.iss`: the installer (Shane's file: change it only when he asks). It copies `prometheus\*` from the folder on disk, so local files such as logs written while playing from the repo go into it too. Since ec16ef6 (2026-11-21) it excludes `Config.txt`, so upgrades keep players' settings and the builder's own settings aren't shipped; the pack creates `Config.txt` with defaults on first start.
- `tools/test-build/make-test-zip.ps1`: makes a tester zip from the last commit (never from disk), named `Prometheus-<label>-test-<yyyyMMdd>-<commit>.zip`, with the installer's layout (`mushclient\` plus `changelog.html`) and `TESTING-README.txt`. It stops if the pack has uncommitted changes. Run it from PowerShell: `.	ools	est-build\make-test-zip.ps1` (optional `-Label word`).

## Sound functions

`PlayGlobalSound(file, pan)`, `PlayRoomSound(file)` and `PlayCombatSound(file, pan)` in `lua/prometheus/core/Sound.lua`. Paths are relative to `sounds/` (Room and Combat add their subfolder). Each respects its on/off setting and volume in `ConfigTable.Settings`.

## Working rules

- Branches: `master` is released, and `dev` is development. Feature work happens on a branch, then a pull request into `dev`. Delete merged branches.
- Commit, and push straight after every commit (Shane's own repo).
- **Never edit `prometheus/version.info` or `prometheus.iss`'s version line either** (Shane, 2026-11-21): like the changelog, Shane manages the version by hand. Committing his changes to them is fine; changing them only when he says so for that specific change.
- **Never edit `changelog.md` or `changelog.html`.** They're Shane's to write (Shane, 2026-11-20). Instead, write the player-facing changes (with issue links) to a notes file in `C:\code\git-src\text-files` for him, put it on his clipboard, and tell him it's there. Committing and pushing his own changelog edits is fine.
- **No merge without the changelog** (Shane, 2026-11-22: "If the changelog isn't updated properly the merge doesn't happen"). Before merging any pull request with a player-facing change: give Shane the note, wait for him to add it to `changelog.md` and `changelog.html`, check his edit (the diff shows the line, and nothing else broke), then commit and push both files on the pull request's branch, and only then merge. If the change isn't player-facing, ask Shane whether it needs a changelog line before merging.
- **Changelog note style** (Shane, 2026-11-22): write each note exactly as a line of `changelog.md`: it starts with `* `, is all lower case (including words like "pa"), says what changed for players in plain words, and ends with the issue link in square brackets, not wrapped in round brackets: `[#54](https://github.com/stickbear2015/prometheus/issues/54)`. Example: `* spdebug no longer reports a missing sound for channels that don't have their own channel sound, such as pa. nothing you hear changes. [#54](https://github.com/stickbear2015/prometheus/issues/54)`
- Players' existing settings must keep working after an update.
- **Every message that goes into a buffer must also go into the All buffer** (Shane, 2026-11-20). Use `AddToHistory(buffer, text, all_text)` from `lua/prometheus/triggers/common.lua`, which sends All first, then the other buffer. Checked 2026-11-20: every buffer message in both test recordings has its All entry.
- Testing: LuaJIT (Lua 5.1 compatible) is installed at `C:\Users\spopp\AppData\Local\Programs\LuaJIT\bin\luajit.exe` (installed 2026-11-20 for the cleanup's test tool). **Its winget install also set the user environment variables `LUA_PATH` and `LUA_CPATH` to LuaJIT's folders, which MUSHclient's Lua obeys: every plugin's `require` (ppi, serialize, prometheus.main) then failed on Shane's PC with "module not found". Both were deleted on 2026-11-21. Never set them; the test tool doesn't need them.** Since #51 (merged in #52), the five plugins that load modules (LuaAudio, channel_history, output_functions, universal_text_to_speech, Prometheus) start by putting this copy of MUSHclient's folders first (`GetInfo(66)` plus `lua/?.lua`, `lua/?/init.lua`, `?.dll`, `lua/?.dll`), so those variables can't break the pack. Any new plugin that uses `require` needs the same block. `sapi_interface`, a text-to-speech fallback, has never been in the pack.

## Cleanup decisions

- **2026-11-20: one Prometheus plugin, split into several files.** `Prometheus.xml` pulls in area files with `<include>` (comms, starship, combat, socials and so on), each with its Lua beside it. It stays one plugin, so the first matching trigger still stops the rest, and settings and sounds stay shared. Not separate plugins, which would each see every line (double sounds) and need their settings passed between them. Decided by Shane after discussing it with another pack developer.
- **Global plugins: dropped** (Shane, 2026-11-20). The pack's plugins stay loaded by the world file, as before.
- **2026-11-20: the cleanup fixes existing problems; it doesn't add things that don't exist** (Shane). For example, no neuter social sounds: the game has no neuter gender, so the missing neuter files aren't a bug and stay as they are.
- Where things are stored: the world file (`.mcl`) holds world settings and its plugin list; `worlds/plugins/state/*-state.xml` holds each plugin's saved variables per world (git-ignored, player-specific); `mushclient_prefs.sqlite` holds global MUSHclient preferences; `Config.txt` holds the pack's own settings (volumes, sound switches, message filters).
